# 複数のボットに仕事を分けてみた
最近は Grokbot 上で、役割ごとに分けた複数のボットに開発を手伝ってもらっています。
コードと GitHub はコーディングマスター、Mac mini の操作は Apple Master、レビューはセキュリティ監視、新しいボットづくりは bot生成マンとプロンプト職人、Grok Build CLI の運用は専任ボット、という分担です。

## 実際の流れ
このブログの記事エディターは、Mac mini 上で Claude Code をヘッドレスで動かして実装しました。
実装後のセキュリティレビューも Claude Code に任せ、出てきた指摘をもとに投稿前の危険な記述チェックを追加しています。
指示は外出先からスマホの音声で出すことも多く、そこからボット同士が作業を引き継いでくれるのはかなり楽です。

## 権限は最小限に
任せるほど怖くなるのが権限です。GitHub のトークンは必要な権限だけに絞った fine-grained PAT を使い、公開ブランチにはブランチ保護をかけました。
変更は必ず PR を経由し、最後のマージだけは自分でやる、というルールにしています。この記事もその流れで出しています。

## やってみて分かったこと
* ボットごとに「できること・やってはいけないこと」をはっきり決めておくと、事故が起きにくい
* 「Mac がオフライン」といった報告は古い情報のこともあるので、鵜呑みにせず確認し直す
* レビュー結果などは要約せず全文を受け取るほうが、判断を誤らない

全部を任せきるのではなく、境界線を引いたうえで任せる。このくらいの距離感が、今のところちょうど良さそうです。
